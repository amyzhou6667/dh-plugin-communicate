## 测试用例设计

### 1. 任务发现模块测试

#### 正常场景
- **TC-TD-001**：成功获取待确认任务
- **TC-TD-002**：过滤已处理任务
- **TC-TD-003**：处理空任务列表

#### 异常场景
- **TC-TD-004**：DeepSeek Harness 连接失败
- **TC-TD-005**：API 响应超时
- **TC-TD-006**：API 响应格式错误

### 2. 飞书集成模块测试

#### 正常场景
- **TC-FI-001**：成功发送文本消息
- **TC-FI-002**：成功发送卡片消息

#### 异常场景
- **TC-FI-004**：飞书认证失败
- **TC-FI-005**：消息发送失败
- **TC-FI-006**：回调消息格式错误

### 3. 状态管理模块测试

#### 正常场景
- **TC-SM-001**：创建任务记录
- **TC-SM-002**：更新任务状态
- **TC-SM-003**：查询超时任务

#### 异常场景
- **TC-SM-004**：数据库连接失败
- **TC-SM-005**：任务不存在
- **TC-SM-006**：状态转换无效

### 4. API网关模块测试

- **端到端测试**：每周
- **性能测试**：每月

## 缺陷管理

### 缺陷分类
1. **P0 (严重)**：系统崩溃、数据丢失
2. **P1 (重要)**：主要功能失效
3. **P2 (一般)**：次要功能失效
4. **P3 (轻微)**：界面问题、提示信息

### 缺陷流程
1. **发现**：测试人员发现缺陷
2. **报告**：创建缺陷报告
3. **分配**：分配给开发人员
4. **修复**：开发人员修复缺陷
5. **验证**：测试人员验证修复
6. **关闭**：关闭缺陷
